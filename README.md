# Inkwell

A word processor that runs entirely in the browser. Live at https://kranmal.github.io/inkwell/

- Fonts, sizes, colours, highlights, styles (Title, Headings, Quote, Code) and document themes
- Edit the built-in styles or create your own, and adjust a theme's fonts and colours
- Lists, indents, alignment, line and paragraph spacing, columns, margins, paper size
- Real pages on screen, with headers, footers and page numbers (optionally different on the first page)
- Footnotes, endnotes and a table of contents that follows your headings and page numbers
- Tables with merged and split cells, shading, border styles and drag-to-resize columns
- Shapes, text boxes and charts (column, bar, line, pie) built from data you type in
- Comments and track changes, with accept and reject, Next and Previous buttons that step through the changes (with a "3 of 17" count), also on Ctrl+Alt+] and Ctrl+Alt+[ (⌥⌘] and ⌥⌘[ on a Mac), and **Compare** to see what changed since a saved version or another file (text, formatting, text boxes, WordArt, footnotes, endnotes, comments and table shading, alignment, borders and column widths; header, footer and page-number changes are listed in a note at the top)
- Pictures, links, page breaks, symbols
- Spelling (UK and US English) and rule-based grammar checking, with a proofing score
- **Accessibility checker** (Review tab): flags pictures without alt text (and lets you type it in place), charts without a title, skipped or empty headings, tables without a header row, vague link text, low colour contrast and runs of blank paragraphs
- Find and replace, word count, read aloud, outline, focus mode, dark mode
- Opens .docx, .html, .txt and .md; saves as .docx, .html, .txt, or a **PDF with selectable text** (or print to PDF)
- **References:** figure/table/equation captions, a table of figures (or tables, or equations) with page numbers, cross-references, an index built from marked entries, citations with a bibliography (APA, MLA, IEEE)
- **Mailings:** mail merge from pasted CSV or spreadsheet data, or from a CSV, JSON or Excel file, with live preview and one-document-per-record printing
- **Equations** (type `\frac{a}{b}`, `\sqrt{x}`, `x^2` and so on; saved as real Word equations), **WordArt** and **SmartArt** (process, cycle, hierarchy, list, pyramid)
- **Sections** with their own header, footer, page-number restart, orientation and margins
- **Tables:** sort, repeat header rows, and formulas such as `=SUM(ABOVE)`
- **Templates** gallery, **version history**, **macros** (record typing and formatting, replay), a **thesaurus** and **translation**, **dictation**, and **document protection**
- Documents autosave in your browser (IndexedDB). Nothing is uploaded.

## Not possible without a server

- **Real-time collaboration and cloud storage.** Inkwell is a static site with no back end, so there is nowhere to sync to. Documents stay in your browser; use Save as .docx to move them.

## Known limits

- Sections: a section can switch orientation and margins (Normal, Narrow, Moderate, Wide) from its break onward, and each page is drawn at its own size and margins on screen (centred, with its own header and footer) in single-column documents. In multi-column documents every page on screen keeps one size and one set of margins, and the section break says what changes. Both are written to .docx and print. Importing a .docx keeps a section's margins only when they match one of the four presets; the document's first section keeps the document margins you have set.
- Document protection is a deterrent that stops editing in Inkwell and sets read-only in the .docx. It is not encryption, and anyone can open the file in another editor.
- Dictation and translation rely on the browser (speech recognition, and the on-device Translator API). They are unavailable in browsers without them. The thesaurus is a built-in list of about 1,000 words.
- Version history keeps the latest snapshots in this browser only. Macros record typing and formatting, not mouse selections.
- Mail merge reads pasted CSV, or a CSV, JSON or Excel (.xlsx, first sheet) file. Excel files are read from the first sheet's stored values and shared strings; formulas show their last saved result, and the Excel path has only been tested on files written by script, not real Excel output.
- Equation input is a LaTeX-style subset, not the full language.
- Pages: long paragraphs and list items split across pages at a line boundary (at least two lines stay on each side), and tables break between rows. A table row taller than a page splits across pages at line boundaries in each text cell (in columns too; see below). A picture, shape or chart is capped on screen to the height of the smallest page body (pictures in table cells a little less, so a row of them fits a page; .docx caps pictures the same way), keeping its shape. A heading is never left alone at the foot of a page or column: it moves on with the start of the block after it. A text box, or a table nested in a cell, taller than a page is capped to the page body and scrolls inside itself on screen (print shows it in full). Repeated table header rows show on continuation pages in print/PDF and Word, not on screen. In multi-column documents text fills the left column, then the right, then the next page. Long paragraphs and list items run on into the next column at a line boundary (at least two lines each side; text and inline pictures are slid into place with temporary wrappers that are never saved). A table row taller than a column is cut at line boundaries in each text cell and the pieces run on into the next columns (each piece keeps the cell's own width, so it wraps narrower than a full column, and the cell's borders and shading are redrawn behind every piece). A block that can't be cut (a picture, a table row, a short paragraph) that doesn't fit moves whole, so a column bottom can be ragged, as in Word; the last page's columns are not balanced. Print and the HTML export use true CSS columns.
- Track changes records text you type, delete or paste, and formatting changes (bold, italic, underline, strike, sub/superscript, font, size, colour, highlight), which you can accept or reject. In Word export a formatting change is written as a Word formatting revision (w:rPrChange) recording the previous bold, italic, underline, strike, font, size, colour, highlight and sub/superscript.
- Phones and tablets: the page starts fitted to the screen width (never above 100%), you can pinch to zoom (25% to 200%), buttons and handles are larger on touch screens, form fields are 16px so iOS does not zoom in on them, and a quick double tap does what a double click does (open a chart, text box, header or footer). It is the same page layout scaled down, not a reflowed mobile layout, so text is small until you zoom in. Dragging across table cells to select a range and dragging column borders need a mouse or stylus (the Table tab commands work by touch). It was checked in the browser's phone and tablet emulation with synthesised touch events, not on a real phone or tablet.
- Compare opens its result as a new document (yours is untouched) with every difference as a tracked change by the author "Compare". It compares text: an edited paragraph is marked in place word by word, so its bold, italic, links and colours are kept (a word that stayed but changed bold, italic, underline, strikethrough, sub/superscript, colour, highlight, font or size is marked as a tracked formatting change, which you can reject to restore the old look; rejecting restores the old look of the changed words even when only part of a bold, italic or linked run changed), and so are any equations, footnote marks, cross-references and other objects inside it. Edited, removed and added table cells and rows are marked (a removed row stays as a struck-out row; after accepting it, an empty row remains to delete), and so are added, removed and replaced pictures. Charts, shapes and SmartArt are compared as whole objects: a changed one shows the old version struck out beside the new one marked as inserted, and an added or removed one is marked as such. A changed link address or a link added or removed shows as a "Link" formatting change that you can reject to restore the old link. Equations are compared the same way: a changed equation shows the old one struck out beside the new one, and an added or removed one is marked. Text boxes and WordArt are compared the same way (a text box is one object, so an edit inside it shows the whole old box beside the new one). Equations and WordArt that were removed appear at the end of their paragraph. Existing tracked changes are treated as accepted first. Documents over about 20 million paragraph pairs show "too large".
- Save as PDF writes the pages as they are laid out on screen (page size, headers and footers, tables, shading, borders, list markers, links, and headings as bookmarks) with real, selectable text. It uses the standard PDF fonts (Helvetica, Times, Courier) with each word stretched to the width it has on screen, not the document's own fonts; characters outside Latin-1 and common punctuation become "?" (the count is reported). Pictures, charts, shapes and SmartArt are included as images. It has been checked in macOS's PDF renderer only, not every PDF viewer. For the document's own fonts, choose "PDF with your fonts embedded" (Chrome or Edge only: the browser asks permission to read the fonts installed on your computer). It embeds each font in the regular, bold, italic or bold italic face the text uses (so also Cyrillic, Greek and so on where the font has them): TrueType fonts and fonts inside .ttc collections as subsets of the glyphs used, and OpenType/CFF (.otf) fonts whole (up to 6 MB, so large CJK fonts are not embedded); a font that is not found, is bigger than that, has CFF outlines inside a collection, or forbids embedding in its licence falls back to the standard fonts for that text, and synthesised bold or italic is not embedded. The embedding was checked with Arial, Georgia, the Helvetica and Avenir collections and the STIX OpenType font in macOS's PDF renderer, not with other fonts or viewers, and the permission prompt itself has not been tried in Chrome. Use Print for exact fonts otherwise.
- The accessibility checker tests rules a program can test: it cannot judge whether alt text is accurate, whether wording is clear, or reading order. Contrast is checked for text with its own colour against the sheet or the nearest shaded cell or highlight, using the WCAG 4.5:1 (3:1 for large text) thresholds. Merged table cells and tiny text are reported as tips. It was not checked against a real screen reader.
- Grammar checking is pattern-based (about 100 rules, including comma splices, long sentences and commonly confused words), so it catches common mistakes rather than everything.
- Charts come in twelve types (column, stacked column, 100% stacked column, bar, line, area, column + lines, scatter, bubble, radar, pie, doughnut) with up to 12 series. A column + lines chart draws the first series as columns and the rest as lines, a scatter chart reads the label column as X values, and a bubble chart does too, then takes the series in pairs (a Y series followed by its size series; a last Y with no size gets equal bubbles). A column + lines chart can plot its lines on a secondary value axis on the right, with its own title. Each chart can show data labels (values, or percentages on pie, doughnut and 100% stacked charts; not on radar charts) and a title on each axis. Bubble sizes are scaled by area against the largest size, and a bubble chart's legend lists the Y series only. In Word export, charts become native Word charts with an embedded workbook, and shapes and text boxes become Word drawing objects, and SmartArt becomes a native Word diagram (data model, layout, style, colours and a pre-drawn copy of the shapes). Word may re-lay a diagram out with its own built-in layout when it is edited, so spacing and colours can then differ from Inkwell's. This has not been opened in Word itself.
- Word import (.docx) keeps text, styles, tables, pictures, footnotes, endnotes, comments, tracked changes, the first section's header and footer, each later section's own header, footer, orientation and page-number restart, the text of text boxes (as plain Inkwell text boxes, without fill, border or position), native Word SmartArt (read from the diagram's text, with the layout mapped to the nearest of process, cycle, hierarchy, list and pyramid, up to 8 items; its own colours and positions are not kept), and native Word charts (column, 100% stacked, bar, line, area, pie, doughnut, scatter, bubble and radar, and column + lines charts with a secondary axis, read from the chart's cached values into editable Inkwell charts, with data labels and axis titles; the chart's own colours, scales and other options are not kept, and charts with no cached data are dropped). A first-page header's text is not kept, only the "different first page" setting, and anchored text boxes and charts become inline ones. Only checked on files Inkwell wrote, not on real Word files.
- In Word export a table of figures is written as plain text with page numbers (not a Word field, so it does not refresh in Word). Word export writes headers, footers, footnotes, endnotes, comments, tracked changes and custom styles. Equations (OMML), section breaks with their own headers, repeated header rows and the protection flag are included. Its XML is checked for well-formedness, but the output has not yet been opened in Microsoft Word itself.

## Run locally

No build step. Serve the folder with any static server:

```bash
python3 -m http.server 8771
```

Then open http://localhost:8771

## Tests

Open http://localhost:8771/tests/layout.html. It drives the app in a hidden frame and checks the page layout in 1, 2 and 3 columns: no overlapping text, nothing outside a page, tall rows split and redrawn, headings kept with their text, pictures, text boxes and nested tables capped, and temporary wrappers removed. The frame runs with `?test`, which uses a separate IndexedDB database, so your saved documents are untouched. These checks cover on-screen layout and the structure of the PDF export, not print or Word.
